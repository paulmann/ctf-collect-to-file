# ctf — Collect To File

`ctf` рекурсивно собирает текстовые файлы каталога в **один документ**,
сохраняя пути относительно корня источника. Инструмент самодостаточный: одна
программа (bash для Linux/macOS, PowerShell для Windows), без зависимостей.

Репозиторий: <https://github.com/paulmann/ctf-collect-to-file>

## Когда использовать

| Задача | Как решается |
|---|---|
| Уложить проект в контекст LLM | `ctf --git all -o context.md .` |
| Ревью ветки, затронувшей 20 файлов | один документ вместо 20 диффов |
| Снимок исходников для аудита | `--metadata` (размер, строки, sha256/12) |
| Влезть в бюджет токенов | `--token-budget N` + `--budget-action` |
| Найти, почему файла нет в выдаче | таблица skip-причин в самом документе |

## Установка на Windows

### Требования

- **PowerShell 7.6+** для установщика (`pwsh`). Движок `ctf.ps1` работает
  и на Windows PowerShell 5.1, но лаунчер и установщик рассчитаны на `pwsh`.
- Прав администратора **не нужно**, если ставить в пользовательский каталог.

### Быстрая установка

```powershell
git clone https://github.com/paulmann/ctf-collect-to-file.git
cd ctf-collect-to-file
pwsh -NoLogo -NoProfile -NonInteractive -File .\install-ctf.ps1
```

Установка по умолчанию — в `%LOCALAPPDATA%\Programs\ctf`; машино-независимый
вариант — `-InstallRoot C:\tools\ctf`. Удаление:

```powershell
pwsh -File .\install-ctf.ps1 -InstallRoot C:\tools\ctf -Uninstall
```

Установщик копирует движок **побайтово** (сам движок не правится), пишет
лаунчер и добавляет его каталог в PATH **пользователя**. Изменение PATH
действует на новые оболочки; уже открытые терминалы надо перезапустить.

### Проверка после установки

```powershell
pwsh -NoProfile -Command "ctf --version"      # ctf v4.0.0
cmd  /c "ctf --version"                        # ctf v4.0.0
```

### Раскладка и почему она такая

```
<InstallRoot>\bin\ctf.cmd   ← лаунчер; только этот каталог попадает в PATH
<InstallRoot>\lib\ctf.ps1   ← движок (побайтово как в репозитории)
<InstallRoot>\lib\ctf.bat   ← штатный лаунчер проекта, для сверки
<InstallRoot>\install-ctf.ps1
```

Движок **намеренно не лежит в PATH**. Это не вкусовое решение, а следствие
двух замеренных дефектов, каждый из которых ломает работу молча:

**1. PowerShell предпочитает `.ps1` и не связывает `--длинные` опции.**
Короткое имя резолвится в `.ps1` раньше, чем в `.cmd`. При этом PowerShell
не связывает аргументы вида `--long-option` с параметрами скрипта. Замеры
на движке, лежащем в PATH:

| Вызов | Ожидание | Фактически |
|---|---|---|
| `ctf --version` | печать версии | сборка: строка `--version` ушла в позиционный `Extension`, в текущем каталоге создан `all---version-files.md` |
| `ctf --ext php --output out.md .\src` | сборка в out.md | ошибка `A positional parameter cannot be found that accepts argument` |
| `ctf --toc` | TOC | сборка `all---toc-files.md` |

**2. `cmd.exe` предпочтёт `.bat`, а штатный `ctf.bat` работает под
`setlocal EnableDelayedExpansion`**, который **удаляет символы `!`** из
аргументов. Замер: путь `B:\!1\for_ctf-collect-to-file` превращался в `B:`,
и сканировался не тот каталог — **без единой ошибки в выводе**.

Поэтому в PATH попадает только `bin\ctf.cmd`, у которого delayed expansion
выключен явно (`DisableDelayedExpansion`), а движок вызывается через
`pwsh -File`. Лаунчер пробрасывает и аргументы, и код возврата, и умеет
работать с путями, содержащими `!`, `&`, пробелы.

### Ручная установка (если установщик недоступен)

```powershell
$dest = "$([Environment]::GetFolderPath('LocalApplicationData'))\Programs\ctf"
New-Item -ItemType Directory -Path "$dest\bin","$dest\lib" -Force | Out-Null
Copy-Item ctf.ps1,ctf.bat,VERSION "$dest\lib" -Force
# затем создайте $dest\bin\ctf.cmd с setlocal DisableDelayedExpansion
# и вызовом: pwsh -NoLogo -NoProfile -NonInteractive -File "%~dp0..\lib\ctf.ps1" %*
[Environment]::SetEnvironmentVariable('Path',
    ([Environment]::GetEnvironmentVariable('Path','User') + ";$dest\bin"), 'User')
```

## Использование

```
ctf [OPTIONS] [EXTENSION] [SOURCE_DIR] [OUTPUT_FILE]
```

```powershell
# все PHP-файлы в один документ
ctf php .\src result.md

# несколько расширений, современная форма
ctf --ext php,js,ts --output bundle.md .\src

# то, что отслеживает git (уважает .gitignore)
ctf --git all -o context.md .

# ровно 120k токенов Python
ctf --ext py --token-budget 120000 -o ctx.md .

# что было бы собрано и какого размера
ctf --stats .\src
ctf --dry-run --ext py .\src
```

### Ключевые опции

| Опция | Смысл |
|---|---|
| `--ext`, `-e` | расширения через запятую; повторяемая; точка необязательна |
| `--exclude`, `--include` | исключить / оставить по glob (`*` пересекает `/`) |
| `--exclude-dir` | исключить имя каталога на любой глубине |
| `--max-depth`, `--max-size`, `--min-size` | ограничения обхода |
| `--git tracked\|all` | отбор через git, а не обход файловой системы |
| `--output`, `-o` | назначение; `-` пишет в stdout |
| `--format`, `-F` | `md` (по умолчанию), `json`, `jsonl`, `txt` |
| `--metadata` | на файл: байты, строки, sha256/12 |
| `--toc`, `--line-numbers`, `--lang-style` | оформление |
| `--strip-bom`, `--truncate-lines` | обработка содержимого |
| `--token-budget`, `--budget-action` | бюджет (`truncate` или `drop`) |
| `--dedup` | байтово одинаковые файлы — один раз |
| `--no-timestamp` | снимает время: вывод становится воспроизводимым |
| `--strict` | код 4, если ничего не собрано |
| `--check-update`, `--update` | самообновление из репозитория |

### Коды возврата

| Код | Значение |
|---|---|
| `0` | успех |
| `1` | ошибка выполнения (ввод-вывод, права, состояние) |
| `2` | ошибка аргументов |
| `3` | ошибка обновления или сети |
| `4` | ничего не собрано и задан `--strict` |
| `90` | ошибка лаунчера (движок или `pwsh` не найдены) |

`--check-update` возвращает `3`, когда доступна новая версия, — годится как
гейт в CI: `ctf --check-update && echo up-to-date || echo update-available`.

## Особенности Windows-порта (замерено на 4.0.0)

Порт PowerShell повторяет bash-версию по формату документа и большинству
опций, но **имена опций не совпадают везде**. Расхождения подтверждены
запуском, а не чтением документации.

| Feature | bash (`ctf.sh`) | Windows (`ctf.ps1` / launcher) |
|:---|:---|:---|
| версия | `-V`, `--version` | `--version`; **`-V` — это `--verbose`**, не версия |
| исключение | `-E`, `--exclude` | `--exclude`; `-E` связано с `--ext` |
| подробный вывод | `-v`, `--verbose` | `-v`, `-Trace`, `--trace`; **`--verbose` молча игнорируется** |
| конфиг | `-c`, `--config` | **не поддерживается** |
| `--print-config` | есть | **не поддерживается** |
| `--files-from -` (stdin) | есть | возвращает `2` |
| `--git tracked` | есть | возвращает `2`, если каталог не git-репозиторий |
| `--files-from`, `--git`, `--binary` | есть | есть длинные формы |

Работающие короткие формы на Windows: `-e` (`--ext`), `-o` (`--output`),
`-F` (`--format`), `-d` (`--max-depth`), `-I` (`--include`), `-n` (`--dry-run`),
`-q` (`--quiet`), `-v` (`--verbose`), `-h` (`--help`), `-L` (`--follow`).
Остальное указывать **длинными формами** — они безопасны, потому что начали
совпадать с именами параметров движка.

**`--verbose` на Windows молча ничего не делает.** Это важнее прочих
расхождений, потому что отказ не виден: аргумент не совпадает ни с одним
параметром движка и связывается с **общим** параметром PowerShell `-Verbose`,
поэтому вызов проходит, выводит как обычно и возвращает `0`. Замерено через
установленный лаунчер на дереве с бинарным файлом — единственный путь, который
печатает строку отладки: `-v` → 1 строка, `-Trace`/`--trace` → 1,
`--verbose` → 0, `-Verbose` → 0. Использовать `-v` или `-Trace`. Учтите, что
отладка в порте вызывается **из одной точки** (детерминированный пропуск
бинарного файла), поэтому она существенно тише bash-версии; полный список
пропущенных файлов даёт `--dry-run` или таблица skip-причин в конце документа.

**Причина расхождений.** PowerShell связывает параметры без учёта регистра,
поэтому пары bash-опций, различающиеся только регистром (`-e`/`-E` для
`--ext`/`--exclude`, `-v`/`-V` для `--verbose`/`--version`), не могут иметь
обе короткие формы. Это ограничение платформы, а не недоделка; подробнее —
в `ctf.ps1 -Help` и `docs/DECISIONS.md`.

**Прочие замечания.**

- Ошибка связывания параметров PowerShell даёт код `1`, а не `2`, как
  заявлено для ошибок аргументов. Код `2` приходит от собственных проверок
  движка (`--git`, `--files-from`).
- Исполнение политики: `RemoteSigned` пропускает локальный файл без
  предупреждений; лаунчер дополнительно передаёт `-ExecutionPolicy Bypass`,
  поэтому скрипт работает и при более строгой политике.
- Переводы строк: в репозитории `ctf.bat` и `ctf.ps1` — **CRLF**
  (принудительно, `.gitattributes`), остальное — LF. Менять это нельзя: LF
  ломает метки и `goto` в `cmd.exe`.
- Движок не имеет директив `#Requires` — это осознанно, ради совместимости
  с PowerShell 5.1. Не добавлять их без синхронизации с апстримом.

## Типовые ошибки и лечение

| Симптом | Причина | Решение |
|---|---|---|
| `ctf --version` начал сборку, появился `all---version-files.md` | движок `.ps1` лежит в PATH, `--длинные` опции не связались | ставить лаунчером из `install-ctf.ps1`, движок держать в `lib\` |
| путь вида `B:\!1\src` превращается в `B:` | лаунчер работает под `EnableDelayedExpansion` | использовать `bin\ctf.cmd` (delayed expansion выключен) |
| `A positional parameter cannot be found` | вызов `.ps1` напрямую с `--long-option` | вызывать через лаунчер или `pwsh -File` |
| `-V` печатает отладку вместо версии | в PowerShell `-V` = `--verbose` | использовать `--version` |
| `--verbose` не добавляет отладочного вывода | аргумент связывается с общим параметром PowerShell `-Verbose`, до движка не доходит | использовать `-v` или `-Trace` |
| `-E '*.md'` ничего не исключает | в PowerShell `-E` связан с `--ext` | использовать `--exclude '*.md'` |
| ожидаемого файла нет в документе | попал под исключение или признан бинарным | смотреть таблицу skip-причин в конце документа; `-v` покажет пропуски |

## Self-update

```powershell
ctf --check-update
ctf --update
ctf --update --update-channel latest
```

Обновление скачивает новый `ctf.ps1`, **проверяет до перезаписи** (минимальный
размер, заголовок, разбор парсером PowerShell), делает резервную копию
с меткой времени и пишет в тот же файл. Соседние `VERSION` и `ctf.bat`
обновляются, если уже существуют рядом. Адрес загрузки можно направить
на зеркало переменной `CTF_UPDATE_BASE_URL`.

## Границы применимости

- Инструмент **не исполняет** ничего из прочитанного: в bash-версии нет
  `eval`, конфиг воспринимается как данные.
- Вывод никогда не собирается сам в себя: выходной файл исключается из
  обхода и это отмечается как `skip_output_file`.
- Запись атомарная: документ собирается во временном файле рядом
  с назначением и переносится на место; сорванный запуск не обрежет
  существующий документ.
- Бинарные файлы пропускаются детерминированно, с причиной в отчёте.
- Схлопывание дублей (`--dedup`) требует `sha256sum`/`shasum`.
